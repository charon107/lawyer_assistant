### 1️⃣ 商事合同（commercial-legal）

**核心定位：** 企业法务的合同全生命周期管理

**覆盖的法律：** 民法典合同编、担保制度司法解释

**具体技能（9 个）：**

| 技能 | 功能 | 典型场景 |
|------|------|---------|
| **cold-start-interview** | 冷启动访谈，学习你的合同手册（销售方/采购方立场） | 首次使用配置 |
| **vendor-agreement-review** | 对照合同手册逐条审查供应商协议，附修订文本 | "帮我看看这份供应商合同" |
| **nda-review** | 快速三色分流（🟢可签/🟡需注意/🔴拦截），非法务人员自助 | 销售收到 NDA 先自己筛 |
| **saas-msa-review** | SaaS 专属审查：自动续约、价格递增、数据迁出、SLA | "这份 SaaS 订阅协议有坑吗" |
| **renewal-tracker** | 合约续约登记册，显示未来 90 天内到期合同 | "哪些合同快到期了" |
| **escalation-flagger** | 将问题匹配至审批上报矩阵，起草审批请求 | "这个条款谁来批" |
| **stakeholder-summary** | 将法律审查翻译成业务语言（2 分钟可读摘要） | "给业务部门一个简版" |
| **amendment-history** | 追溯合同从基础协议到各补充协议的变更轨迹 | "这个合同改过几次了" |
| **matter-workspace** | 多客户事项隔离工作区 | 律所多客户场景 |

**定时代理（后台自动运行）：**

| 代理 | 监控内容 | 频率 |
|------|---------|------|
| renewal-watcher | 续约到期预警，0-13 天红色报警 | 每周一 |
| deal-debrief | 近期已签协议的合同手册偏差分析 | 每周一 |
| playbook-monitor | 某条款被修改 5 次以上时提议更新合同手册 | 数据驱动 |

**核心设计理念：** 学习的是**你的合同手册**（你的立场、你的标准、你的可接受范围），不是通用模板。首次运行会访谈你并要求提供 5-10 份已签协议来学习。

### 2️⃣ 公司并购（corporate-legal）

**核心定位：** 并购交易全流程 + 董事会治理 + 主体合规管理

**覆盖的法律：** 公司法（2024 修订，限期认缴制、股东失权）

**具体技能（10 个）：**

| 技能 | 功能 | 典型场景 |
|------|------|---------|
| **cold-start-interview** | 模块化访谈：并购/董事会/公众公司/主体管理 | 首次配置，按角色选模块 |
| **diligence-issue-extraction** | 读取数据室文件，按类别提取问题清单 | "审一下数据室里的 200 份文件" |
| **tabular-review** | 表格化审查：一行一文件，一列一数据点，输出 Excel | "从这 200 份合同里提取控制权变更条款" |
| **deal-team-summary** | 分层简报：执行层/交易牵头方/工作团队 | "给 CEO 一个一页摘要" |
| **material-contract-schedule** | 根据尽调发现制作重大合同披露函 | "需要重大合同清单" |
| **closing-checklist** | 自更新交割检查表：哪些事项在阻断 | "交割前还差什么" |
| **board-minutes** | 根据日历自动识别会议，按公司格式起草纪要 | "帮我写上次董事会纪要" |
| **written-consent** | 股东会/董事会书面决议，从先例库检索 | "起草一份股东会决议" |
| **entity-compliance** | 主体合规追踪器：备案期限、合规体检、工商报告导入 | "哪些主体年报快到期了" |
| **integration-management** | 交割后整合：D1/30/90/180 工作计划、合同概括转让 | "并购后整合进度如何" |

**定时代理：**
- **dataroom-watcher** — 监控数据室新文件上传，标记高优先级，运行交割检查表（每周）

**核心设计理念：** 支持买方和卖方两种视角。问题提取有重要性阈值——不会读每一份文件，而是按金额/风险排名。

### 3️⃣ 劳动用工（employment-legal）

**核心定位：** 中国企业劳动法全流程，**管辖地差异**是核心价值

**覆盖的法律：** 劳动合同法、劳动争议调解仲裁法、各省/直辖市地方规定

**具体技能（16 个）：**

| 技能 | 功能 | 典型场景 |
|------|------|---------|
| **cold-start-interview** | 学习你在哪些省/直辖市有员工，读取劳动规章制度 | 首次配置 |
| **hiring-review** | 录用通知书 + 竞业限制审查，管辖地检查 | "这个 offer 有问题吗" |
| **termination-review** | 解除审查，含高风险标记、经济补偿计算 | "辞退这个员工要赔多少" |
| **policy-drafting** | 起草劳动规章制度，含各省/直辖市补充条款 | "帮我起草考勤制度" |
| **wage-hour-qa** | 工资工时问答，管辖地差异适配 | "上海最低工资多少" |
| **worker-classification** | 劳动关系认定——劳社部发〔2005〕12 号三要素 | "这个用工算劳动关系吗" |
| **expansion-kickoff** | 启动跨省/直辖市用工规划 | "我们准备在广东招人" |
| **expansion-update** | 更新跨省用工跟踪表 | "广东那边进展如何" |
| **investigation-open** | 启动内部调查事项 | "收到举报要调查" |
| **investigation-add** | 向调查添加文件/访谈/观察 | "又发现新证据" |
| **investigation-query** | 对调查日志提问 | "证人说了什么" |
| **investigation-memo** | 起草/更新调查备忘录 | "可以写调查报告了" |
| **investigation-summary** | 从调查备忘录起草受众摘要 | "给 HR 一个简版" |
| **leave-tracker** | 未结假期事项预警 | "谁的产假快到期了" |
| **log-leave** | 添加新假期记录 | "张三开始休年假了" |
| **handbook-updates** | 劳动规章制度修改前后 diff | "更新制度有什么影响" |

**定时代理：**
- **leave-tracker** — 涉及法定硬性期限的假期预警：年休假、产假、病假、婚假（每周一）

**核心设计理念：** 插件**故意不存储**各省市的实体法律规则（最低工资、竞业限制补偿等），而是**审查时实时检索**——因为这些数据经常变。

### 4️⃣ 隐私数据（privacy-legal）

**核心定位：** 个人信息保护合规全流程

**覆盖的法律：** 个人信息保护法、数据安全法、网络安全法

**具体技能（7 个）：**

| 技能 | 功能 | 典型场景 |
|------|------|---------|
| **cold-start-interview** | 学习你是处理者还是受托处理者，读取隐私政策和 DPA 模板 | 首次配置 |
| **use-case-triage** | 快速分类：需要 PIA / 可以继续 / 停止 | "用行为数据做广告个性化可以吗" |
| **dpa-review** | 双向审查个人信息处理协议（自动检测你是哪一方） | "客户发来的 DPA 能签吗" |
| **dsar-response** | 个人信息主体权利响应：验证→定位→豁免→起草 | "有人要求删除个人信息" |
| **pia-generation** | 按内部格式生成个人信息保护影响评估 | "新功能需要做 PIA 吗" |
| **reg-gap-analysis** | 新法规 vs 当前政策/实践的差异分析 | "新规出来对我们有什么影响" |
| **policy-monitor** | 扫描隐私政策与实践的偏差 | "我们的政策和实际做法一致吗" |

**核心设计理念：** DPA 审查是**双向**的——同一技能既处理你作为处理者（保护运营灵活度）时收到的协议，也处理你作为受托处理者（保护数据）时收到的协议。

### 5️⃣ 知识产权（ip-legal）

**核心定位：** 商标、著作权、专利、商业秘密和开源合规

**覆盖的法律：** 商标法、专利法、著作权法、反不正当竞争法

**具体技能（10 个）：**

| 技能 | 功能 | 典型场景 |
|------|------|---------|
| **cold-start-interview** | 学习维权姿态、IP 组合、审批矩阵 | 首次配置 |
| **cease-desist** | 起草或分类侵权警告函（发送/接收两种模式） | "有人抄我们的设计" |
| **takedown** | 信息网络传播权通知（发送/回应/反通知） | "有人盗用我们的内容" |
| **clearance** | 商标可注册性检索初筛 | "这个名字能注册商标吗" |
| **fto-triage** | 自由实施初步分析——产品是否被他人专利阻碍 | "我们的产品会侵权吗" |
| **invention-intake** | 发明披露初筛：新颖性、创造性、可授权主题 | "这个发明值得申请专利吗" |
| **infringement-triage** | 侵权初步分析：忽略/沟通/警告函/起诉 | "发现侵权怎么处理" |
| **ip-clause-review** | 审查合同中的 IP 条款 | "这份合同 IP 归属合理吗" |
| **oss-review** | 开源许可证合规检查 | "我们用的开源库合规吗" |
| **portfolio** | 注册续展跟踪：什么到期、什么需要行动 | "哪些商标快到期了" |

**定时代理：**
- **ip-renewal-watcher** — IP 组合续展/宣誓/维护事项预警（每周）

**重要说明：** 本插件**不撰写专利权利要求**——那是专利代理师的专业工作。专利工作限于 FTO 初步分析和条款审查。

### 7️⃣ 监管合规（regulatory-legal）

**核心定位：** 法规动态监测 + 政策差距分析 + 合规差距追踪

**覆盖的法律：** 行政处罚法、行政复议法（2023 修订）

**具体技能（6 个）：**

| 技能 | 功能 | 典型场景 |
|------|------|---------|
| **cold-start-interview** | 学习关注哪些监管机构，索引政策库，建立重要性阈值 | 首次配置 |
| **reg-feed-watcher** | 即刻检查法规动态，报告新增内容 | "有什么新规定" |
| **policy-diff** | 对比特定法规变化与政策库的差异 | "这个新规影响我们哪些政策" |
| **gaps** | 未闭合差距追踪器 | "有哪些待整改的合规问题" |
| **comments** | 审查征求意见稿，记录决策，跟踪期限 | "这个征求意见要回复吗" |
| **policy-redraft** | 起草标记修订的政策重述草案 | "帮我改政策来闭合差距" |

**定时代理：**
- **reg-change-monitor** — 法规动态监测，按重要性阈值过滤，发布简报（每周，法规活跃时每日）

**核心设计理念：** **重要性过滤**是核心价值——不会对每条部门动态都报警。与 privacy-legal 的 reg-gap-analysis 搭配使用：本插件负责**自动监测**，隐私插件负责**深度分析**。

**覆盖的法律：** 生成式 AI 管理办法、算法推荐管理规定、深度合成管理规定

**具体技能（7 个）：**

## 🔑 跨模块共同设计模式

1. **冷启动访谈** — 每个模块首次使用都访谈你，学习**你的做法**，不是套通用模板
2. **来源溯源标签** — 所有引用标注 `[法条原文]`/`[检索工具]`/`[模型知识—需验证]`
3. **确认门禁** — 高后果动作（发送、签署、提交）需明确确认
4. **matter-workspace** — 多客户隔离，防止上下文泄露
5. **持续学习** — 实践画像随使用不断改进，代理提议更新
